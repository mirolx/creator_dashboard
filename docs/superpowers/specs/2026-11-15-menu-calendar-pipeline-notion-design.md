# 메뉴 분리 · 캘린더 · 파이프라인 · Notion 연동 설계

- 작성일: 2026-11-15
- 참고: Prize Pilot(사용자 본인 프로젝트)의 홈 / 캘린더 / 파이프라인 메뉴 구조
- 상태: 설계 검토 중

## 1. 왜

- 지금은 `/[platform]` 한 페이지에 위젯 9개(일정·체크리스트·칸반·트렌드·아이디어·레퍼런스·해시태그·메모·성과)가 모여 있어서 복잡하다. 기능별로 메뉴를 나눠 한 화면에 한 가지 일만 보이게 한다.
- 편집·업로드 일정을 **캘린더**에서 잡고, 영상 진행 상태를 **파이프라인 보드**에서 단계별로 옮기고 싶다.
- 영상별 작업 문서는 이미 노션 **'콘텐츠'** DB(영상 하나 = 페이지 하나)에서 관리한다. 파이프라인 카드에서 버튼 한 번으로 그 DB에 페이지를 만들고 바로 열고 싶다.

## 2. 목표 / 비목표 / 반목표

**목표**
1. 플랫폼(유튜브·인스타) 안에서 **홈 / 캘린더 / 파이프라인 / 탐색 / 설정** 메뉴로 페이지를 나눈다.
2. 파이프라인: **아이디어 → 촬영 → 편집 → 예약 업로드 → 게시 완료** 5단계. 카드는 드래그나 단계 메뉴로 옮긴다.
3. 카드마다 **촬영일 · 편집 마감일 · 업로드일**을 두고, 캘린더는 이 날짜들을 모아서 보여준다. 캘린더에서 블록을 다른 날로 끌면 카드 날짜가 바뀐다.
4. 카드의 **노션 버튼**: 연결된 페이지가 없으면 '콘텐츠' DB에 행을 만들고 새 탭으로 연다. 있으면 그냥 연다.
5. 노션 페이지가 연결된 카드의 제목·단계·세 날짜가 대시보드에서 바뀌면 노션에도 반영한다(**대시보드 → 노션 한 방향**).
6. '게시 완료' 카드에 **보관함으로 옮기기** 버튼을 둔다. 옮긴 카드는 파이프라인에서 사라지고 **보관함** 메뉴에서 볼 수 있다. 보관함에서 다시 꺼낼 수도 있다.
7. 쓰지 않는 **레퍼런스(최근 저장한 레퍼런스)** 와 **해시태그 뱅크** 기능을 없앤다.

**비목표**
- 노션 → 대시보드 동기화. 노션에서 바꾼 값은 대시보드에 들어오지 않는다.
- 카드를 삭제할 때 노션 페이지 삭제.
- 노션의 다른 속성(콘텐츠 유형·우선순위·썸네일 등) 다루기.
- 캘린더 주간 보기. 이번에는 월간 보기만 만든다.
- 다른 사용자를 위한 Notion OAuth.

**반목표** (돌아가더라도 실패로 보는 것)
- 노션 호출이 실패해서 대시보드 저장까지 막히는 것. 대시보드 저장이 먼저이고, 노션 반영 실패는 따로 알린다.
- 노션 토큰이 브라우저로 나가는 것. Notion API는 서버에서만 호출한다.
- 기존 칸반 카드·일정 데이터가 사라지는 것.

## 3. 제약

- Next.js 16.3 — 코드 작성 전에 `node_modules/next/dist/docs/`에서 해당 내용(라우팅, Server Actions)을 확인한다(AGENTS.md).
- Supabase + RLS. 위젯은 `useLiveList` + `tableData`로 낙관적 업데이트하고 Realtime으로 동기화한다. 새 코드도 이 패턴을 따른다.
- DB 마이그레이션은 사용자가 Supabase SQL Editor에서 직접 실행한다(기존 0001~0004와 같은 방식). 새 코드를 배포하기 전에 실행해야 한다.
- 한/영 메시지(`messages/ko.json`, `en.json`) 둘 다 추가한다.
- 사용자가 Vercel에 직접 넣을 환경변수: `NOTION_TOKEN`(Sensitive), `NOTION_DATA_SOURCE_ID`. `.env.example`과 README에는 이름만 적는다.

## 4. 고려한 방식 (캘린더 일정 저장)

| 방식 | 내용 | 장단점 |
|---|---|---|
| **A. 카드가 날짜를 가짐 (선택)** | `kanban_cards`에 촬영일·편집 마감일·업로드일 컬럼을 두고, 캘린더는 이 날짜들을 모아서 보여준다. 영상과 무관한 일정은 기존 `schedule_items`에 남긴다. | 영상 하나에 날짜가 한 곳에만 있어서 두 번 입력할 일이 없다. 노션 날짜 속성 3개와 1:1로 맞는다. |
| B. 일정을 따로 두고 카드에 연결 | `schedule_items`에 `card_id`를 달아 연결한다. | 자유도는 높지만 날짜가 두 군데로 나뉘고, 노션에 어느 날짜를 보낼지 애매하다. |

사용자가 **A**를 골랐다.

## 5. 설계

### 5-1. 메뉴와 라우트

```
/[platform]            홈
/[platform]/calendar   캘린더
/[platform]/pipeline   파이프라인
/[platform]/explore    탐색
/[platform]/archive    보관함
/[platform]/settings   설정 (기존)
```

- 헤더 첫 줄: 플랫폼 탭(유튜브 / 인스타그램)과 로그아웃. 둘째 줄: 메뉴 탭(홈·캘린더·파이프라인·탐색·보관함·설정). 기존 `PillTabs`를 재사용한다. `WorkspaceTabs`에 섞여 있던 설정 탭은 메뉴 탭으로 옮긴다.
- 플랫폼 탭을 누르면 같은 메뉴의 다른 플랫폼 페이지로 간다(캘린더에서 인스타를 누르면 `/instagram/calendar`).
- **홈:** 오늘·이번 주 일정(카드 날짜 + 기타 일정), 체크리스트, 단계별 카드 수 요약(누르면 파이프라인으로 이동), 성과(준비 중).
- **탐색:** 트렌드(유튜브만), 아이디어, 메모. 기존 위젯을 그대로 옮긴다.
- **없애는 기능:** 레퍼런스와 해시태그 뱅크.
  - `src/features/references`, `src/features/hashtags` 폴더를 지운다.
  - `loadDashboard`, `WORKSPACE_TABLES`, 타입(`ReferenceItem`, `Hashtag`, `REFERENCE_KINDS`)에서 이 둘을 뺀다.
  - 한/영 메시지 키도 지운다.
  - DB 테이블(`reference_items`, `hashtags`)과 저장된 데이터는 지우지 않고 둔다. 나중에 필요하면 따로 정리한다.
- 각 페이지는 기존처럼 `WorkspaceRealtime`으로 감싸고, 필요한 테이블만 불러온다(`loadDashboard`를 페이지별로 나누거나 테이블을 골라 부르게 바꾼다).

### 5-2. 데이터 — 마이그레이션 `0005_pipeline_calendar.sql`

`kanban_cards`:
- `status` 제약을 바꾼다: `idea`, `shoot`, `edit`, `scheduled`, `published`.
- 기존 값 옮기기: `shot → shoot`, `editing → edit`, `review → edit`, `uploaded → published`.
  - 기존 `shot`은 새 카드가 처음 들어가던 칸이라 '촬영'으로 둔다.
- 새 컬럼 `shoot_on date`, `edit_due_on date`, `upload_on date`(모두 null 가능, 시간 없이 날짜만). 날짜는 한국 시간 기준이다.
- 새 컬럼 `notion_page_id text`(null 가능). 동기화에 쓴다. `notion_url`은 버튼이 열 주소로 계속 쓴다.
- 새 컬럼 `archived_at timestamptz`(null 가능). null이면 파이프라인에 있는 카드, 값이 있으면 보관함 카드다.

`schedule_items`는 그대로 둔다(영상과 무관한 일정용).

`src/lib/types.ts`의 `KANBAN_STATUSES`와 `KanbanCard` 타입도 맞춰서 바꾼다.

### 5-3. 파이프라인 페이지

- 5단계 칸을 가로로 놓는다. 좁은 화면에서는 가로 스크롤한다.
- 카드에 보이는 것: 제목(바로 편집), 다가오는 날짜 하나(예: '업로드 D-3'), 단계 드롭다운, 노션 버튼, 펼치기.
- 펼치면 세 날짜 입력칸과 삭제 버튼이 나온다.
- 이동 방법은 두 가지다.
  - HTML5 드래그 앤 드롭(라이브러리 없음).
  - 단계 드롭다운. 터치 기기와 키보드 사용자는 이걸로 옮긴다.
- 같은 칸 안의 순서는 기존 `position`과 `positionAfter`/사이값 계산으로 정한다.
- 새 카드는 '아이디어' 칸 맨 아래에 들어간다.
- 기존 노션 링크 직접 입력 UI는 없애고 노션 버튼 하나로 대신한다. 기존 `notion_url` 값은 그대로 둔다.

### 5-4. 보관함

- '게시 완료' 칸의 카드에만 **보관함으로** 버튼이 보인다. 누르면 `archived_at`에 지금 시각을 넣는다.
- 파이프라인과 홈의 단계별 카드 수는 `archived_at is null`인 카드만 센다.
- **보관함 페이지:** 보관한 카드를 업로드일 최신순으로 목록으로 보여준다(업로드일이 없으면 보관한 날짜순).
  - 행마다 제목, 업로드일, 노션 버튼, **파이프라인으로 되돌리기** 버튼이 있다.
  - 되돌리면 `archived_at`을 null로 바꾸고 '게시 완료' 칸 맨 아래로 돌아간다.
  - 삭제 버튼도 있고, 누르면 확인을 한 번 거친다. 파이프라인 카드의 삭제는 지금처럼 펼친 카드 안에 그대로 둔다.
- 노션에는 보관 여부를 보내지 않는다. 노션의 상태는 '게시 완료'로 남는다.
- 캘린더에는 보관한 카드의 날짜도 그대로 보인다. 지난 업로드 기록을 남기기 위해서다. 다만 블록을 흐리게 표시한다.

### 5-5. 캘린더 페이지

- 월간 그리드(월~일). 이전 / 다음 / 오늘 버튼이 있다.
- 칸 하나에 들어가는 블록:
  - 카드 날짜 블록: `촬영 · 제목`, `편집 마감 · 제목`, `업로드 · 제목`. 종류별 색이 다르다.
  - 기타 일정(`schedule_items`) 블록.
- 블록을 다른 날짜 칸으로 끌면 해당 날짜가 바뀐다.
  - 카드 블록이면 카드의 그 날짜 컬럼이 바뀐다.
  - 기타 일정 블록이면 `scheduled_at`의 날짜만 바뀌고 시각은 유지된다.
- 끌기가 안 되는 환경을 위해 Prize Pilot처럼 "블록을 눌러 고른 뒤 날짜를 누르면 이동"도 지원한다.
- 날짜 칸의 + 버튼으로 기타 일정을 추가한다.
- 카드 블록을 누르면 날짜를 고치는 작은 팝오버가 열린다. 팝오버에는 파이프라인으로 가는 링크도 있다.
- 그리드 아래에 '날짜 없는 카드' 목록을 둔다. 여기서 카드를 날짜 칸으로 끌면 업로드일로 잡힌다.

### 5-6. Notion 연동

- 서버 전용 모듈 `src/lib/notion/`:
  - `fetch`로 Notion REST API를 직접 호출한다(SDK는 쓰지 않는다).
  - 토큰은 `NOTION_TOKEN`에서 읽는다.
  - API 버전은 data source를 parent로 쓰는 최신 버전이다.
- 대상: '콘텐츠' DB의 data source `8818195e-fee9-4942-b7a4-a18d9b53adfe`(환경변수 `NOTION_DATA_SOURCE_ID`).
- 속성 매핑:

| 대시보드 | 노션 속성 | 값 |
|---|---|---|
| title | 제목 (title) | |
| status | 상태 (select) | idea→아이디어, shoot→촬영 예정, edit→편집 중, scheduled→예약 업로드, published→게시 완료 |
| shoot_on | 촬영일 (date) | 날짜만, null이면 비움 |
| edit_due_on | 편집 마감일 (date) | |
| upload_on | 업로드일 (date) | |

- 노션에만 있는 상태(기획 중·촬영 완료·검수 중·보류)는 쓰지 않는다.

- **Server Action `openNotionPage(cardId)`:**
  1. 로그인 확인 후, RLS가 걸린 서버 클라이언트로 카드를 읽는다(남의 카드면 실패).
  2. `notion_page_id`가 있으면 `notion_url`을 돌려준다.
  3. 없으면 위 매핑대로 페이지를 만들고, `notion_page_id`·`notion_url`을 카드에 저장한 뒤 URL을 돌려준다.
  4. 클라이언트는 받은 URL을 새 탭으로 연다.
     - 팝업 차단을 피하려고, 클릭 즉시 `window.open()`으로 빈 탭을 먼저 열고 나중에 주소를 넣는다.
- 기존 카드에 직접 붙여 둔 `notion_url`만 있고 `notion_page_id`가 없으면, URL 끝의 32자리 ID를 꺼내 `notion_page_id`로 저장하고 그 페이지를 연결 페이지로 쓴다. 꺼낼 수 없으면 링크만 열고 동기화하지 않는다.
- **Server Action `syncNotionPage(cardId)`:**
  - 연결된 카드의 제목·단계·날짜가 바뀌면, 브라우저 저장이 성공한 뒤에 호출한다.
  - 현재 카드 값 전체로 노션 페이지 속성을 덮어쓴다.
  - 연속으로 고치는 경우를 생각해 카드별로 짧게 디바운스한다(약 1초).
  - 실패하면 카드에 "노션 반영 실패 · 다시 시도" 표시를 띄운다. 대시보드 값은 그대로 둔다.
- `NOTION_TOKEN`이 없거나 DB에 통합이 연결되지 않아 권한 오류가 나면, 버튼을 눌렀을 때 원인을 알려 주는 메시지를 보여준다.
- 유튜브와 인스타 카드 모두 같은 DB에 만든다. 플랫폼 구분 속성은 이번에 쓰지 않는다.

### 5-7. 사용자가 할 일 (배포 전)

1. notion.so/my-integrations에서 내부 통합을 만든다. 콘텐츠 읽기·수정·추가 권한이 필요하다.
2. '콘텐츠' DB의 ··· → 연결에서 그 통합을 추가한다.
3. Vercel(필요하면 `.env.local`에도)에 `NOTION_TOKEN`, `NOTION_DATA_SOURCE_ID`를 넣는다.
4. Supabase SQL Editor에서 `0005_pipeline_calendar.sql`을 실행한다.

## 6. 테스트

- 순수 함수 단위 테스트(vitest):
  - 상태 ↔ 노션 상태 이름 매핑, 카드 → 노션 properties 변환(날짜 null 포함)
  - 노션 URL에서 페이지 ID 꺼내기
  - 월간 그리드 날짜 계산(월요일 시작, 앞뒤 달 채우기)
  - 카드 → 캘린더 블록 변환
  - 드롭 위치 → position 계산
- 브라우저 확인(dev 서버):
  - 메뉴 이동과 플랫폼 전환
  - 파이프라인 드래그와 드롭다운 이동
  - 캘린더 블록 이동과 날짜 반영
  - 노션 버튼으로 생성 → 열기 → 다시 누르면 같은 페이지
  - 단계 변경이 노션에 반영되는지
- 기존 테스트, typecheck, lint, build가 모두 통과해야 한다.

## 7. 구현자에게 맡기는 것

- 컴포넌트를 어떻게 나눌지, 파일 위치(`src/features/pipeline`, `src/features/calendar` 등).
- 블록 색, 간격 같은 세부 스타일. 기존 디자인 시스템(`Card`, `pillClass`, 토큰)을 따른다.
- 홈 요약 카드의 구체적인 모양.
- 디바운스 구현 방식.

## 8. 구현자가 정한 사항 (사용자 확인용)

- '촬영' 단계는 노션 '촬영 예정'으로 보낸다.
- 기존 `shot` 카드는 '촬영', `review` 카드는 '편집'으로 옮긴다.
- 캘린더는 월간 보기만 만든다.
- 날짜 없는 카드를 캘린더로 끌면 업로드일로 잡는다.
- 플랫폼 구분 없이 같은 노션 DB를 쓴다.
- 보관 버튼은 '게시 완료' 카드에만 보인다. 보관해도 노션은 바꾸지 않는다.
- 보관한 카드도 캘린더에는 흐리게 남긴다.
- 보관함에서 되돌린 카드는 '게시 완료' 칸으로 돌아간다.
- 보관한 카드를 삭제할 때는 확인을 한 번 거친다.
- 레퍼런스·해시태그는 화면과 코드에서만 없애고, DB 테이블과 데이터는 남긴다.
